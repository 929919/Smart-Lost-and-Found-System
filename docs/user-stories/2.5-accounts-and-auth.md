## Story
> As a **user**, I want to sign in to an account so that the system knows who I am and what I am allowed to do.

## Acceptance criteria
- [x] Sign-in requires a JCU ID and a password
- [x] Invalid credentials are rejected without creating a session
- [x] The access level comes from the account, not from user choice
- [x] Signing out clears the session

## Implementation
`db/users.sql` defines the `users` table with row-level security and `verify_login()`, a `SECURITY DEFINER` function that checks credentials inside the database. `assets/js/auth.js` calls it; passwords never reach the browser.
